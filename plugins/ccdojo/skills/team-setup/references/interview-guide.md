# 業務ヒアリングガイド（フェーズ 1）

> チームの質はここで決まる。**埋まっていない項目を勝手に推測して設計に進まない。**
> 一度に全部聞かず、`AskUserQuestion` などで**塊ごとに**聞く。すでに会話で分かっている項目は飛ばす。
> 回答者が業務の当事者本人とは限らない（代理で答えている場合もある）。分からない項目は「当事者への確認が必要」と明示して保留する。

## 聞く順番（6 ブロック）

下記 6 ブロックを上から順に。各ブロックの「最低限」が埋まれば次へ進んでよい。

### ブロック 1：事業の輪郭

- 業種・何で売上を立てているか（物販／受託／SaaS／店舗／メディア…）
- **ブランド/商材/チャネルは複数あるか**（複数なら名前と特徴。例：実店舗＋EC、複数ブランド）
- 会社規模（おおよその人数）。1 人〜数人なら兼務前提のスリムなチームにする
- **最低限**：業種 ＋ 単一か複数事業か

### ブロック 2：機能領域（部門・職能）

> ここで挙がった領域が、そのまま**ペルソナ1体＋ディレクトリ1つ＋部門 CLAUDE.md 1本**になる。
> 粒度を決めるつもりで聞く。

- 日々の業務をどんな「かたまり」で動かしているか（例：制作・マーケ・営業・CS・経理・開発・仕入…）
- それぞれ誰がやっているか（専任 or 兼務）
- AI エージェントに**特に任せたい領域**はどこか（優先順位）
- **最低限**：主要な機能領域 4〜8 個

### ブロック 3：繰り返し発生する具体タスク

- 毎週/毎月くりかえす定型作業（例：レポート作成・記事執筆・見積もり・SNS 投稿・請求書発行…）→ **ワークフロー候補**
- 「これを自動化できたら嬉しい」作業トップ 3
- 各タスクの典型的な成果物の形（文書／表／コード／画像／HTML…）
- **最低限**：頻出タスク 3〜5 個と、その成果物形式

### ブロック 4：リスク・コンプラ・品質ゲート

- 守るべき法令・業界規制はあるか（例：景表法・薬機法・金商法・個人情報・医療・建築…）→ **レビュアー候補**
- 外部公開物（広告・LP・SNS・プレス）で表現上 NG なことはあるか
- 扱うデータの機微度（個人情報・顧客データ・機密の取引条件など）
- 品質基準・ブランドトーンの決まりはあるか
- **最低限**：リスク源が「ある/ない」と、あるなら種類

### ブロック 5：承認・意思決定

- **不可逆 or 外部公開 or 高コスト**な工程はどれか（例：送信・公開・発注・課金・本番反映）→ **承認ゲート候補**
- 誰が最終承認するか（多くの場合は経営者＝プリンシパル）
- 「ここは必ず人間が見たい」という工程
- **最低限**：人間承認が要る工程の有無

### ブロック 6：環境・運用

- 使うのは Claude Code で確定か（プロジェクト直下に `.claude/` を作れるか）
- **すでにフォルダ構成があるか**（あれば見せてもらう）→ 部門ディレクトリの命名をそれに合わせる。無ければ `NN_領域名/` を既定にする
- よく使う外部サービス・MCP（スプレッドシート・CRM・チャット・分析ツール等）→ レビュアーのツール制限やコマンド設計に効く
- 出力の既定の形（文書中心？ コード中心？ 画像？ HTML レポート？）
- 呼び出し時の好み（日本語/英語、トーン）
- **最低限**：対象環境の確認（Claude Code 前提）

## ヒアリング結果のまとめ方

集めた情報を次の「設計インプット表」に整理してからフェーズ 2 に渡す。

```
## 設計インプット
- 事業: <業種 / 単一・複数事業 / 規模>
- 機能領域: <4〜8個>
- 頻出タスク: <3〜5個 + 成果物形式>
- リスク源: <法令/コンプラ/データ機微度。無ければ「なし」>
- 承認が要る工程: <あれば列挙。無ければ「なし」>
- 環境: <生成先プロジェクトのパス / 併用ツール・MCP / 出力形式の好み / 言語>
- ディレクトリ命名: <既存構成に合わせる or `NN_領域名/`>
- 担当の呼び方: <人名で統一 or 役職名で統一>
```

## 推論のヒント（機能領域 → ペルソナの当たり付け）

ヒアリングが薄いときの叩き台（**そのまま採用せず必ず本人に確認**）：

- 物販/EC 系 → 制作（ページ/LP）・マーケ（集客/SNS）・分析（売上/在庫）・CS・経理 ＋ 法務レビュアー（広告表現）
- 受託/制作会社 → 制作・ディレクション・営業/提案・経理 ＋ 品質レビュアー
- メディア/コンテンツ → 編集/執筆・SEO・SNS 運用・分析 ＋ 法務/校閲レビュアー
- 開発会社/SaaS → 設計・実装・レビュー・QA・ドキュメント ＋ セキュリティレビュアー
- 店舗系 → 接客/研修・販促・仕入/在庫・分析・経理

いずれも「司令塔 1 ＋ 専門 4〜8 ＋ レビュアー 0〜4」に収める。
