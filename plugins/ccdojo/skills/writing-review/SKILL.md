対象: $ARGUMENTS（未指定なら、どのファイルを見るかユーザーに聞いてから始める。`git status` で変更中の文章ファイルがあれば候補として挙げる）

このスキルは、前後を読まないと判断できない文体の癖を見る。役割は下読みで、最終判断は人がする。
ルールの考え方は `/ccdojo:writing` に書いてある。こちらはその検品版。

## 手順

1. このスキルのフォルダにある `references/rules.md` を読み、`- ` で始まる行を1項目ずつ取り出す（グループ見出し `###` は項目ではない）
2. 文章1本 × ルール1項目につき `ccdojo:style-rule-checker` サブエージェントを1体起動する。**全項目ぶんを1回のメッセージで並列に**起動し、各エージェントには「文章のパス」と「担当するルール1項目の全文」だけを渡す。ほかのルールは渡さない
3. 結果を集約して、文章ごと・ルールごとに違反箇所を報告する
   - 複数のルールが同じ行を指していたら、1つにまとめて「〜と〜の両方」と書く
   - 「違反なし」だったルールは、末尾に一覧でまとめる（1行）
   - 修正案はエージェントが書いたものをそのまま載せる。集約側で書き足さない
4. **修正はしない。** どれを直すかはユーザーが決める。直す指示が来たら、そのとき本文を編集する

## 報告の形

```
## docs/xxx.md

### 【無生物主語】 2件
- 12行目: 「探す手間が、そのまま待ち時間になります」
  → 探す手間が増えるほど、待たされます
- 40行目: …

### 【述語に「誰が？」】 1件
- …

違反なし: 主語の立て直し / 英語の型 / …
```

## 使わない場面

- `CLAUDE.md` `README.md` などの内部文書。ルールは読者に出す文章のためのもの
- プロジェクト固有の決まり（コードブロックの種別、用語の統一など）。それは各リポジトリの CLAUDE.md や lint が見る
