# writing-review が見るルール

数えれば分かるもの（太字の個数・指示語の個数・種類なしコードフェンス）は、lint や `grep` に任せる。
ここにあるのは、前後を読んで判断しないと分からないものだけ。
ルールの考え方は `/ccdojo:writing` に書いてある。

書き方の約束: 1項目 = `- ` で始まる1行（改行しない）。`/ccdojo:writing-review` はこの単位でエージェントを1体ずつ立てる。
各項目は「何を探すか → 違反にしないもの → ✗/✓」の順に書く。
プロジェクト固有の項目を足すときは、このファイルをコピーして自分のリポジトリに置き、そちらを読ませる。

### 文（英語の直訳を疑う）

- 【無生物主語】モノ・コト・抽象名詞を主語にして他動詞を続けている文を探す。人を主語にするか、主語を省くか、自動詞に変えれば直る。道具が実際に動作する文（「Claude Code がファイルを開きます」）は違反にしない。✗ 推測させないことが、そのまま速さになります → ✓ 推測せずに済むぶん、速くなります ／ ✗ 探す手間が、そのまま待ち時間になります → ✓ 探す手間が増えるほど、待たされます ／ ✗ この記事が VS Code を使う理由 → ✓ VS Code を使う理由
- 【主語の立て直し】「ここが」「これが」「それが」「それは」「この〜が」で文を起こし、直前の文の内容を受け直しているものを探す。消しても通じるなら違反。日本語は前の文から主語を引き継ぐので、毎文で立て直すと英語の直訳に見える。✗ ここが大事なところです。この4つは、業務が変わっても同じです → ✓ 4つとも、業務が変わっても同じです
- 【英語の型】英語の定型をそのまま訳した言い回しを探す。「この記事を読み終えると〜できるようになります（By the end of）」「共通しているのは〜という形です（What these have in common is）」「〜が要点です・肝です（The key is）」「〜することが重要です（It is important to）」「〜してみましょう」の連発（Let's）、「言い換えれば（In other words）」、「〜と言えるでしょう」、「注目すべきは〜（What's notable is）」など。到達目標を書くこと自体は違反ではない。記事ごとに違う言い方で、地の文として書いてあればよい
- 【指示語の多用】これ・それ・あれ・こちら・ここ・そこ が1本の文章に4個以上あるか、名詞に戻せば読みやすくなる箇所を探す。this / that / it を1対1で訳すと増える。「ここまでで」「そこで直せば」「これだけです」のような慣用は自然なので違反にしない。✗ これは能力の問題ではありません → ✓ 能力の問題ではありません
- 【名詞止め・モノ主語の説明文】本文の文が名詞や「〜が必要。」「〜の確認。」で終わっているもの、状態をモノ主語で説明しているものを探す。狙いは読者に向けた告知・状態表示の文（UI 文言や案内）で、「〜が原因です」「〜の合図です」「これで終わりです」のように事実を述べる普通の説明文は違反にしない。例を並べるだけの一文は次の文で受けていれば違反にしない。見出し・表のセル・箇条書きの短い項目も違反にしない。✗ メールアドレスの確認が済んでいません → ✓ メールの確認がまだです ／ ✗ この記事は会員限定です → ✓ 続きは登録すると読めます
- 【同じ書き出しの反復】複数の段落・節・記事が同じ型（「〜では、」「まず、」「〜とは、」など）で始まっているものを探す。3回以上続いたら違反。機械が書いたものに見える最大の原因。1本の中でも、まとめて書いた複数本でも同じ

### 一文検品（一文だけ取り出して成立するか）

- 【述語に「誰が？」】文頭で立てた主語と述語がねじれている文を探す。述語の動作主が主語と違うなら違反。✗ この教材は、任せられるところまで、順番に進みます（進むのは読者。主語は教材） → ✓ この教材は、任せられるところまで、順番に案内します
- 【動詞に「何を？」】目的語が省かれていて、直前の文から補えないものを探す。書き手には自明でも初見の読者は補えない。文章の冒頭と要約はとくに厳しく見る（読者はまだ文脈を持っていない）。✗ 入れるところから始めて → ✓ Claude Code を入れるところから始めて
- 【到達点は現在地との差分】「〜できるようになる」「〜まで進む」と書いた到達点が、読者がいまもできることになっていないかを探す。✗ 毎月くり返している仕事が、自分の手で回るところまで（読者はいまも手で回している） → ✓ 毎月くり返している仕事を、任せられるところまで
- 【動作主の欠落】道具がするのか読者がするのか、文から復元できない文を探す。「〜のは、〜からです」「〜してから、〜します」の構文と、手順文でとくに出る。前の文から動作主を引き継げているものは違反にしない（日本語は主語を引き継ぐ）。✗ フォルダの中を見にいって、しばらく考えてから、下書きを作ります → ✓ Claude Code がフォルダの中を見て、下書きを作ります

### タイトル・要約・見出し

- 【タイトルはメリットを言う】教材・LP のタイトルが、問題提起・疑問形・「〜とは」「〜について」型になっていないかを探す。読むと何ができるようになるかが書いてあれば合格。`##` 見出しは「〜とは」「〜について」型だけ拾う。疑問形の見出し（「どう使い分けるか」）は読者の問いで章立てした構成なので違反にしない。✗ 同じ頼み方なのに差がつくのは、フォルダのせい → ✓ フォルダを整えるだけで、指示が一度で通るようになる
- 【本文にない約束をしない】タイトル・要約・見出しに出てくる数字（「5つの」「15分で」）と程度（「ここまで減る」「失敗しなくなる」「必ず」）を拾い、本文に根拠や同じ数の項目があるかを照合する。数が合わない、本文に答えが無い、なら違反。✗ 毎月の作業はここまで減る（どこまで減るのか本文に無い） → ✓ 15分で、使える状態になる（本文に「15分くらいです」がある）
- 【比べるなら何と何か】「違い」「差」「〜より」と書いてあるのに、比較相手が同じ文か見出しの中に無いものを探す。読者は1本目から読むとは限らない。✗ 何が違う道具なのかを知る → ✓ いつものチャット AI と、どこが違うのか
- 【要約と節末の決め台詞】要約文と、各節の最後の段落で、理由も例も無い短い断定が2文以上続く箇所を探す。要約は問いかけで始めてよいが、言い切りの連打は違反。✗ 使いすぎると止まります。ただ、止まるだけです。 → ✓ 使いすぎると止まりますが、時間が来れば戻りますし、勝手に請求が増えることもありません

### 体裁（数えられないもの）

- 【疑似見出しの太字】段落の頭に太字で小見出しを置き、そのまま本文を続けているものを探す（英語ブログの型）。見出しにするなら `###`。文中で読み飛ばされると詰まる箇所を1語だけ太くしているのと、箇条書きの項目名（「- **症状** — 対処」の型）は違反にしない
- 【行き先のない先送り】「あとで扱います」「別の機会に」「ここでは触れません」と書いて、リンクも1行の答えも無い箇所を探す。リンクがあるか、その場で答えを1行書いてあれば合格。行き先の無い先送りは、読者には答えが無いのと同じ
- 【専門語を消さない】やさしい言い換えのせいで、読者が次に自分で調べるときの用語が本文から消えている箇所、または専門語を初出で説明せずに使っている箇所を探す。判定は「読者が次に調べるときに要るか」の一点。✗ 一度に覚えていられる量には限りがあります（で終わる） → ✓ コンテキストと呼びます、と名前を渡してから量感を説明する
