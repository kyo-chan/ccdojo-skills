# 画像を忠実にHTML再現する

## 手順の全体像

1. 元画像のサイズ・比率から用紙／画面サイズを確定
2. 元画像から再利用する素材を抽出（写真・スクショ・イラスト）
3. 主要ブロックの座標を実測し、パーセント配置でHTMLを組む
4. ヘッドレスChromeでレンダリングし、元画像と並べて差分を潰す
5. （重要な案件のみ）サブエージェント3観点でレビューさせる

## 1. サイズの確定

```bash
python3 -c "from PIL import Image; im=Image.open('元画像.png'); print(im.size, im.width/im.height)"
```

- 縦横比 1:1.414 → A判（A4/A3/A2/A1…）。**印刷用途なら実寸mmで組む**
- A1=594×841mm / A2=420×594 / A3=297×420 / A4=210×297
- 用紙サイズが決まったら `mm/px` 係数を出す（例：841mm ÷ 3179px = 0.2646mm/px）。以降すべての実測値をこの係数でmmに換算する

## 2. 素材抽出

`scripts/extract_assets.py` を使う。主な機能：

- `crop` … 白枠・パネル境界を自動検出してタイトに切り出す（外周に元の地色が残るのを防ぐ）
- `recolor` … HSVで特定の色相域だけを別色に置換（例：黄色のイラスト背景→緑）。肌色・黒線は彩度/明度条件で保護される
- `cutout` … 外周からのフラッドフィルで白背景を透明化し、連結成分で対象だけを残す（円形マスクだと筆致が欠けるので使わない）

```bash
# 白枠の内側を自動検出して切り出す（--box はおおよその範囲でよい）
python3 scripts/extract_assets.py crop    元画像.png shot.png --box 0.09,0.34,0.50,0.54 --auto --white-edge 3
# 黄色系（色相25〜70度）だけを緑（色相142度）に置換。彩度0.35以下は保護されるので肌色・白は残る
python3 scripts/extract_assets.py recolor 元画像.png char.png --from-hue 25,70 --to-hue 142 --sat 0.85 --val 0.79
# 背景を透明化してイラストだけ抜く（最大成分の範囲外にある文字などは自動で捨てる）
python3 scripts/extract_assets.py cutout  元画像.png char.png --box 0.65,0,1.0,0.27
```

recolor と cutout を組み合わせる場合は、**recolor を先に**かけてから cutout する（透明画素があると色判定が乱れるため）。

**素材抽出でよくある失敗**

| 症状 | 原因 | 対処 |
|---|---|---|
| 切り出し画像の外周に元の地色が細く残る | 目測で切っている | 中央の行/列から境界を走査して内側を検出（`crop` の自動検出） |
| イラストの一部が直線的に欠ける | 円形マスクで切り抜いた | `cutout`（フラッドフィル＋連結成分）に変える |
| 肌色や白背景まで色が変わる | 色相だけで判定している | 彩度 `s > 0.35` 等の条件を併用する |

## 3. レイアウトを組む

- ルート要素を実寸（`width:594mm; height:841mm`）で作り、内部は `position:absolute` + `%` で配置する。flexは同一行の並びだけに使う
- **フォントサイズは mm 指定**。元画像の字面高を測り、mm換算した値を使う
- 画面プレビューは、実寸要素を `transform:scale(0.3)` し、固定サイズのラッパーで囲む（`overflow:hidden`）。`@media print` で実寸に戻す

```css
@page{ size:594mm 841mm; margin:0; }
.wrap{ width:178.2mm; height:252.3mm; margin:0 auto; position:relative; overflow:hidden; }
.poster{ position:absolute; left:0; top:0; width:594mm; height:841mm; transform:scale(0.3); transform-origin:top left; }
@media print{ .wrap{ width:594mm; height:841mm; overflow:visible; } .poster{ transform:none; } }
```

- 画像は base64 で内包すると単一ファイルで配布できる（数MBまで）。`scripts/build.py` が雛形

**レイアウトでよくある破綻**

| 症状 | 原因 | 対処 |
|---|---|---|
| 縮小プレビューで縦横比が崩れる | flexアイテムが縮んだ | ラッパー方式にする（上記CSS） |
| 蛍光ペン風の下線が見えない | `z-index:-1` が親の背景より後ろに行く | 親に `isolation:isolate`、擬似要素は `z-index:0`、文字側を `z-index:1` |
| 見出しが2行に折り返して他要素に重なる | 字詰めが足りない | `white-space:nowrap` + `letter-spacing` を詰める（日本語見出しは −0.05〜−0.12em が実用域） |
| 並べた画像の高さが揃わない | 幅%だけ指定している | 素材のアスペクト比に合わせて幅%を決める（実素材の実比で分配する） |

## 4. レンダリング検証

```bash
"/Applications/Google Chrome.app/Contents/MacOS/Google Chrome" --headless --disable-gpu --no-sandbox \
  --hide-scrollbars --window-size=2245,3179 --force-device-scale-factor=0.5 --virtual-time-budget=8000 \
  --screenshot=preview.png "file:///絶対パス/full.html"
```

- 実寸版HTML（プレビュー縮小を無効化したもの）を撮ると比較しやすい
- `scripts/compare.py 再現版.png 元画像.png` … 差分%と、上下に分割した比較画像（上=元／下=再現）を書き出す
  - **トーン変更を伴う場合、差分%は30%超が普通**（色が違うので当然）。数値は同トーン比較・修正前後の比較に使い、色替え案件では比較画像の目視を主軸にする
- **上半分・下半分に切って並べて目視する**のが最も効く。数値だけでは字間や形状の劣化に気づけない

## 5. サブエージェントによるレビュー（重要案件のみ）

3体を並列で走らせ、**観点を分けて**検証させる。同じファイルを同時に編集させず、報告だけさせて修正は自分で統合する。

1. **レイアウト・構図** … 各ブロックの位置/幅/高さを元画像のピクセル実測から%換算させ、CSSの現在値と突き合わせ
2. **タイポグラフィ・文言** … 文言の一字一句、字面高のmm換算、ウェイト、強調表現、改行位置
3. **配色・ディテール** … 元の色役割（主役色/濃色/地色）の写像が保てているか、コントラスト比、アイコンやイラストの形状劣化

各エージェントには「元画像のピクセル座標を実測すること」「修正値まで具体的に書くこと」「ファイルは編集しないこと」を必ず指示する。

## トーン変更（色替え）を伴う場合

元デザインの**色の役割構造**を写し取る。単に色相を回すのではない。

1. 元画像から主要色を実測し、役割を割り出す（主役色＝見出し/枠、濃色＝ベタ面、淡色＝パネル地、アクセント＝マーカー）
2. 同じ役割関係になるよう新色パレットを組む。**明度・彩度の関係を保つ**のが要点（元の淡色地が S41 なら、新しい淡色も S40 前後にする。S9まで落とすとパネルが消える）
3. 元で同色だった要素は新パレットでも同色にする（例：フッター帯とバッジ円が同じ濃色だったなら、緑版でも同じ濃緑にする）
4. 白文字・アクセント文字のコントラスト比が元より落ちていないか検算する

イラスト素材の色替えは `recolor`（HSVの色相域指定）で行い、肌色・黒線を巻き込まないよう彩度条件を付ける。
